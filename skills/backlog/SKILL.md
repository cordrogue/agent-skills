# Backlog

The project has no issue tracker. Out-of-scope problems go in [`docs/BACKLOG.md`](../../../docs/BACKLOG.md), and any skill that says to file an issue, ticket, or backlog item means that file.

- Don't fix an out-of-scope problem in the current change. File it and keep going.
- One line per entry. Name the problem, not the fix.
- File it under the closest existing group. Add a group only when none fits.
- When an entry needs more than a line, write a `docs/work/` paper and link it.
- Before adding, check for an existing entry. Update or merge it instead of duplicating.
- Remove an entry when its problem is fixed, in the same change as the fix.
- Mention what you filed in your reply to the developer.
